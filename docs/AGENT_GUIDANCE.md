# hearth implementation guidance

Read [development](DEVELOPMENT.md), [current build status](implementation/BUILD_STATUS.md) and [design coverage](implementation/DESIGN_COVERAGE.md) before changing the application. The numbered design documents, phase plans and original brand package are the product baseline. Their immutable snapshot is in `docs/plan/`; preserve it and keep implementation decisions in `docs/adr/` and `docs/implementation/`. All paths in commands are relative to the repository root. Keep substantive guides under `docs/`; the root README and AGENTS files remain discovery pointers.

The current product name is always written lowercase: `hearth`, including titles and sentence starts. The combined logo uses the fireplace symbol as the first h followed by `earth`; never place a separate symbol beside the full wordmark. Follow the [active brand guide](brand/BRAND_GUIDE.md) and preserve the historical v1.0 snapshot. Keep protocol identifiers, existing filenames and user-authored content intact when editing brand copy.

Use the fixed architecture: Python control plane, PostgreSQL, native Go workers, and separate React admin/user bundles sharing the supplied brand assets. The Python appliance helper is a development tool, not a substitute for the product installer or member management protocol.

Default to a distributed farm of concurrently resident specialists. Place different models on different machines and route each capability request to a qualified, available model target on its hosting machine. Support multiple instances of every provider type and many-to-many capability bindings. Multiple models on one machine remain optional, subject to its actual memory and shared capacity. Avoid model loading or swapping in the normal request path; treat lifecycle changes as explicit setup or management work. Independently resourced machines must be able to serve work concurrently. The current two-service, shared-GPU development arrangement is temporary evidence, not the deployment default. Follow [ADR 0006](adr/0006-managed-and-external-providers.md#distributed-residency-is-the-default) and qualify residency separately from connectivity.

Keep desired state, observed state and verified readiness separate. A running process, loaded model name, heartbeat, UI specimen or passing fixture does not prove product readiness. Default to local-only content and zero cloud budget. Do not make paid provider calls without a concrete authorized budget.

Security boundaries are product behavior. Never turn headers, model output, tool output, hostnames or retrieved content into authority. Models do not receive admin credentials or execution grants. Verify signed packages and recipes before activation; general shell execution is not a worker command.

Existing external LAN providers may use HTTP after explicit administrator risk acceptance for that saved connection. Keep the visible warning, scoped approval, audit/revocation, private-address checks and HTTPS validation. Do not require users to install a connector or certificates for an approved existing HTTP service. hearth-managed runners retain automatic TLS as their intended default. Follow [the external HTTP decision](implementation/EXTERNAL_HTTP_PROVIDERS.md), which supersedes the earlier external-provider TLS-only restriction.

Keep secrets and runtime artifacts in ignored `.hearth/`, never in source, URLs, command arguments or committed evidence. Use the pinned SSH maintenance channel only for the isolated developer appliance. Keep database migration and application roles separate; tests must not bypass RLS to make application access pass.

After contract changes, run `uv run --group knowledge python scripts/dev.py generate`. Relevant checks are `uv run --group knowledge python scripts/dev.py check`, `uv run --group appliance python scripts/development_stack.py qualify-linux`, and `HEARTH_LIVE_UI=1 pnpm test:e2e`. The Linux Switchyard build must retain its pinned source and CPU baseline because the public AVX2 wheel does not run in the qualified WHPX guest. The reference guest also requires the shadow-stack compatibility setting in ADR 0005. Real identity browser QA may only provision an empty disposable farm; never remove an established user's data to make tests run.

Update the implementation ledger with observed results and explicit missing work. Keep all 61 release gates at their real status. Required local 3D and the P8 portions of A12 must not disappear from scope.
