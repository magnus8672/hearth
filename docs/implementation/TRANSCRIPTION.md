# hearth microphone and transcription

> Current status, 18 September: transcription is implemented, but no transcription provider is registered in the active farm. The prepared CPU Whisper service below describes historical qualification. Memory, shared tools and geometry have since been implemented as bounded slices. See [the dated farm snapshot](CURRENT_STATE.md) and [current coverage](DESIGN_COVERAGE.md).

Implemented 13 September 2026. Private chat now records a microphone or accepts a PCM WAV upload, transcribes it through the assigned local `audio.transcribe` provider and saves a transcript draft. It does not submit a chat turn. Users review or edit the transcript, choose **Use in message**, then send or steer through the existing composer.

## Try it

Refresh [your workspace](https://hearth.example.invalid) and open Private chat. Below the message composer, choose **Record voice**, allow the browser microphone permission, speak and click **Stop recording**. The recording can be played back, discarded or submitted with **Transcribe recording**. **Upload WAV** follows the same review flow. Recording stops automatically at two minutes. Permission is requested only after clicking Record voice; discard, navigation and component teardown stop microphone tracks, including a permission response that arrives after cancellation.

Edit the resulting **Review transcript** text and choose **Use in message**. Existing composer text is preserved. Nothing sends automatically, including during another model's response; the usual Send/Steer action remains explicit. The composer retains its 4,000-character limit and rejects an oversized combined draft without truncation. Original transcript drafts survive reload and keep their transcription model identity. Unapplied edits are browser-local and protected by the unsaved-change prompt. **Dismiss transcript** clears the stored draft text in the control database.

The historically prepared provider was `faster-whisper-small.en`, running on CPU with an independent resource group. This first recipe recognizes English. It supports recordings from half a second through two minutes, and WAV uploads up to 8 MiB with mono/stereo 16-bit PCM at 8/16/24/32/44.1/48 kHz. Unsupported, silent, truncated or excessive files produce an explicit error. MP3, M4A, WebM, FLAC, other languages, live partial transcripts and speaker diarization remain future work.

Administration supports multiple transcription servers and ordered capability assignments. **Verify transcription** sends a bundled known recording and checks normalized word error rate, as well as job identity and manifest continuity. It requires at most 25% word error on that phrase. This is a bounded English modality check, not broad accuracy certification. The [activation receipt](../../evidence/transcription/2026-09-13/activation.json) records the actual prepared farm assignment without changing existing routes.

## Boundaries and validation

Migration `0017` adds forced owner/farm RLS transcription jobs. The browser submits audio and an idempotency identifier; the server selects the provider and constructs the immutable audio digest and route receipt. Input is decoded with Python's bounded PCM WAV parser and normalized to mono 16-kHz PCM, stripping container metadata. No external media URLs, compressed codecs, command execution or content-derived authority enter this path. The reference Python 3.12 runtime uses `audioop` for rate/channel conversion; replacement is required before a Python 3.13 upgrade.

The provider receives only the normalized recording, not chat history or credentials for other services. Transcription keeps one active job per account and requires a verified idle pool. The runtime loads the selected model once at startup with CPU int8 execution; no request loads or swaps a GPU model. Lost execution receipts fence the pool as unknown without replay. Cancellation drains the current recognition segment before releasing capacity. Session revocation, archive, provider changes and manifest mismatch prevent publication.

The control database clears raw audio when a job settles or is reconciled as interrupted. The provider removes its temporary WAV on completion/failure/cancellation and cleans leftover inputs at restart. Backups or SQLite/filesystem remnants are not secure-erasure guarantees. Provider receipts and transcript text remain in its private development job store, limited to 1,000 jobs; full cross-provider retention/deletion remains open. The control workspace allows 100 undismissed transcript drafts per account. Dismissed idempotency records remain, with transcript/audio/metadata cleared.

The [live test](../../evidence/transcription/2026-09-13/live-transcription.json) used real CPU Whisper, authenticated provider transport and restricted PostgreSQL/BFF APIs with explicit OIDC fixtures in a disposable farm. A second synthetic English recording, different from the provider probe, transcribed with zero normalized word errors and restored in a fresh session without creating a chat message. Browser qualification uses Chromium's fake microphone source through actual getUserMedia and AudioWorklet APIs. It verifies recording, WAV creation, stopped tracks, late permission cancellation, playback preview, upload, editable review, reload, cancellation and multiple independent servers. It does not certify the user's physical microphone or every browser.

See [qualification and deployment](../../evidence/transcription/2026-09-13/validation.json) for exact test counts, HTTPS asset/backend hashes and scope. Desktop and mobile screenshots were inspected. All fourteen profiles now have bounded implementations. All 61 full release gates retain their existing open status.

Refreshing the existing Qwen provider exposed the old 256-token text-probe budget returning no visible answer. Verification now allows 4,096 tokens for reasoning plus the short answer and requires a normal completion rather than accepting a truncated reply. Targeted regressions cover reasoning before visible text and rejection of output-limited probes. This does not change interactive reply budgets or add automatic inference retries.

Next priorities are physical provider loss/recovery, busy-machine handling and live Switchyard integration. Shared tools, private memory and local geometry now have bounded implementations. Managed enrollment and their full qualification remain open.
